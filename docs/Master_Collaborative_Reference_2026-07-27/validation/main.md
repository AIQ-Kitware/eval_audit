We have reached consensus on the central story:

> EEE detects reproducibility gaps. ## Additional concerns found in the independent review

### 1. Report freshness is not result freshness

The paper and its artifact should record three separate states:

- **run-artifact freshness**: model outputs came from the intended execution path;
- **comparison freshness**: the correct targets, joins, normalization, and deduplication were used; and
- **report freshness**: plots and tables were regenerated using the latest reporting code.

A timestamp on a report establishes only the third item unless a manifest links all three.

### 2. The six-category taxonomy needs an orthogonal success axis

The mismatch taxonomy explains *why* two executions disagree. The paper should separately state *what* it is reproducing:

1. **Artifact reconstruction** - recomputing official scores from released outputs;
2. **Procedural reproduction** - rerunning a recipe under a pinned or declared equivalent instrument; and
3. **Claim-level robustness** - determining whether substantive rankings or improvement claims survive plausible substrate variation.

Released artifacts remain the historical ground truth for the reported score. Reruns test procedural stability and identifiability rather than replacing that record.

### 3. Non-identifiability must be scoped to the evidence examined

The historical conclusion should be written as:

> non-identifiable from the surviving public and repository evidence examined

rather than as an absolute claim that no additional private archive could ever resolve the instrument.

### 4. EvalAudit's current claim should remain a capability claim

The defensible statement is that EvalAudit supports exact-spec replay, execution-provenance preservation, layered comparison, and controlled diagnosis. It should not yet be claimed to guarantee reproducible evaluation or to "fix HELM" without fault-injection validation, overhead measurements, and completed end-to-end cases.

### 5. Live-only evidence should receive an attestation artifact

For every live-store or post-archive Git claim used in the paper, the release should contain a machine-generated attestation with:

- path or object identifier;
- SHA-256 hashes;
- creation and modification times;
- code commit and dirty state;
- frozen run specifications and public targets;
- model/tokenizer/deployment revisions;
- container and hardware identity; and
- the commands used to generate and compare the result.

This will retire the collaborator-verified qualification.

## Final consensus on the paper

There is no remaining substantive disagreement about the paper's core thesis or near-term story.

### Consensus thesis

> A public LLM benchmark recipe is not a complete experimental record. Benchmark reproduction is a layered system-identification problem spanning recipe, deployment, execution instrument, and artifact interpretation. Controlled reconstruction can attribute and sometimes close apparent gaps, while some historical measurements remain non-identifiable from the surviving evidence examined.

### Consensus narrative

1. EEE normalizes results and detects discrepancies.
2. EvalAudit builds the machinery to replay exact recipes, preserve execution provenance, compare artifacts layer by layer, and search latent deployment parameters.
3. OLMo is the partially recoverable modern case, with probe-level precision/engine evidence that still requires ordinary-path confirmation.
4. RedPajama demonstrates execution under declared historical proxy instruments.
5. GPT-J/GPT-NeoX/OPT demonstrate origin-instrument non-identifiability from the surviving record.
6. The paper derives a minimum execution-provenance and release standard.
7. A narrow Qwen comparison may demonstrate why substrate control matters for current small-model progress, but the paper does not depend on it.

None on the scientific story. The remaining work is operational:

With those qualifications incorporated, I consider the chronology and paper strategy to have reached consensus.
